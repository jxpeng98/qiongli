# Qiongli v2.0.0

Qiongli 2.0.0 is the first stable release of the Rust-native CLI, built from
`main`. It combines the program, research Skills, templates and Lite/Full MCP in
one native executable. Keep your preferred Host and model; use Qiongli to retain
sources, review changes and continue research across stages.

穷理 2.0.0 是从 `main` 构建的原生 CLI 首个正式版。程序、研究 Skills、模板和
Lite/Full MCP 随同一个可执行文件交付。你仍可使用自己选择的 Host 和模型，
穷理负责保留来源、支持修改审阅，并让研究在不同阶段之间继续推进。

## From 1.x to 2.0 / 从 1.x 到 2.0

The familiar research activities remain. The change is in their runtime,
installation and continuity. This comparison refers to late 1.x, including the
retained 1.19 compatibility baseline; earlier releases differ.

阅读、设计和写作等研究任务仍然保留。变化主要在运行时、安装方式与项目连续性。
以下对照以 1.x 后期及保留的 1.19 兼容基线为参照，不代表每个旧版本都完全相同。

| Area / 方面 | Late 1.x / 1.x 后期 | 2.0 |
|---|---|---|
| Runtime / 运行时 | Python full runtime; native Lite bundles / Python 完整运行时，另有原生 Lite 包 | Rust CLI with native Lite and Full MCP / Rust CLI 与原生 Lite、Full MCP |
| Delivery / 交付 | Python and npm entries had different responsibilities / Python 与 npm 入口职责不同 | Same CLI contract across GitHub, npm, PyPI and Cargo / 四个渠道共用原生 CLI 能力 |
| Installation / 安装 | More surface and part choices / 较多 surface 和 parts 选项 | Guided install and update, with verified Host registration / 安装与更新共用向导，核验 Host 注册 |
| Skills | More prescribed sequences and quotas / 更多预设步骤与数量要求 | Task-led guidance with evidence and protocol boundaries / 按任务提供指导，保留证据和协议边界 |
| Graph | Literature citation discovery and expansion / 文献引文发现与扩展 | Project claims, evidence locations, decisions and gaps in offline HTML / 项目论点、证据位置、决定和缺口可在离线 HTML 中查看 |
| Continuity / 连续性 | Workflow artifacts and handoffs / 工作流产物与交接 | Structured capture, revision checks and traceable stage summaries / 结构化采集、版本核验与可追溯阶段总结 |
| Collaboration / 协作 | Workflow roles and orchestration conventions / 工作流角色与编排约定 | Source-bound tasks and returns using actual Host agents / 通过真实 Host 代理执行，任务与返回绑定来源 |
| Maintenance / 维护 | Python runtime and several distribution paths / Python 运行时与多条分发路径 | Shared Rust services and canonical content, with version-bound packages / 共享 Rust 服务与规范内容源，渠道包绑定版本 |

Late 1.x Marketplace Plugins already offered independent native Lite execution.
2.0 extends native delivery to the complete CLI and Full MCP; it does not claim
to have introduced every native feature. The native path removes the Python
runtime requirement, but no measured speedup or maintenance-cost reduction is
claimed merely because the implementation uses Rust.

1.x 后期的 Marketplace 已有独立原生 Lite 插件。2.0 将原生交付扩展到完整 CLI 和
Full MCP，并非所有原生能力都从本版开始。原生执行路径不再需要 Python，但这不能
直接换算成经过测量的性能提升或维护成本下降。

Read the detailed comparison, practical limits and migration steps:
[English guide](https://github.com/jxpeng98/qiongli/blob/v2.0.0/docs/guide/whats-new-2.md) ·
[中文指南](https://github.com/jxpeng98/qiongli/blob/v2.0.0/docs/zh/guide/whats-new-2.md).

## Download and run / 下载后直接使用

Choose the complete archive for your platform from **Assets**, verify it against
`SHA256SUMS`, then extract and run `./qiongli --help` (Windows PowerShell:
`.\qiongli.exe --help`). No separate Python, Node.js, Rust or package manager is
needed. The executable includes research content and both MCP profiles.

从 **Assets** 选择对应平台的完整压缩包，核对 `SHA256SUMS` 后解压运行。
不需要先装 Python、Node.js、Rust 或包管理器；研究内容和两种 MCP 都已包含在程序里。

| Platform / 平台 | Complete archive / 完整压缩包 |
|---|---|
| macOS Apple Silicon / ARM64 | `qiongli-2.0.0-aarch64-apple-darwin.tar.gz` |
| Windows x64 | `qiongli-2.0.0-x86_64-pc-windows-msvc.zip` |
| Linux x64, glibc 2.35+ | `qiongli-2.0.0-x86_64-unknown-linux-gnu.tar.gz` |

Windows includes the C runtime in the executable. Supported operating-system
libraries remain required. Host applications and online accounts are separate.
GitHub's automatic **Source code** archives are not runnable binary packages.
Intel macOS, Linux ARM64 and native Windows ARM64 are outside this asset set.

Windows 已内嵌 C 运行库，系统库仍需符合支持条件。Host 应用和在线账号单独配置。
GitHub 自动生成的 **Source code** 是源码；本次附件不包含 Intel macOS、Linux ARM64
或 Windows ARM64 原生包。

## Package channels / 包管理器渠道

Choose one channel; these are alternatives, not three required steps.
以下任选一种，不需要连续安装三个渠道：

```sh
npm install --global qiongli@2.0.0
python -m pip install --upgrade "qiongli==2.0.0"
cargo install qiongli --version 2.0.0 --locked
```

npm needs Node.js 18+, PyPI Python 3.9+, and Cargo Rust 1.97+ plus a native linker.
npm `latest` selects stable releases; `next` may remain on the earlier Beta.
Cargo has no `next` tag. All three channels provide `qiongli` and `ql`.
Cargo publishes the CLI and its eight shared library crates as one versioned
dependency set; users install only `qiongli`. Publication runs through Actions.

npm 需要 Node.js 18+，PyPI 需要 Python 3.9+，Cargo 需要 Rust 1.97+ 和本机链接器。
正式渠道使用 npm `latest`，`next` 可能仍指向旧 Beta；Cargo 没有 `next` 标签。
三个渠道都提供 `qiongli` 和 `ql`。Cargo 发布 CLI 及其依赖的八个共享库 crate，
用户只需安装 `qiongli`。发布继续通过 Actions 完成。

## Install and update the Plugin / 安装与更新 Plugin

Run `qiongli install`, or `qiongli install plugin` to install or refresh the
registered source. `upgrade plugin` and `update plugin` share this flow. Confirm
the file preview and official Host registration separately. The local Plugin
includes Skills and Full MCP (32 tools); native Marketplace platform archives
include Skills and Lite MCP (14 tools). Both use bundled native executables.
Stable archives retain the `qiongli-next` installation identities.

运行 `qiongli install` 打开向导，或用 `qiongli install plugin` 安装和更新已登记的源目录。
文件预览与官方 Host 注册分别确认。本地 Plugin 包含 Skills 和 Full MCP（32 个工具），
原生 Marketplace 平台包包含 Skills 和 Lite MCP（14 个工具），都使用随包原生程序。
正式版沿用 `qiongli-next` 安装身份，避免只因发布渠道变化而更换插件标识。

Compared with beta.6, known Codex Plugin conflicts can now be migrated after
confirmation. Only the listed old entries are disabled; sources, caches and
unrelated settings are preserved. Changed configuration or unknown entries stop
the operation. Claude keeps manual conflict handling. Installation results now
group paths and verified state in a compact summary, with session and Hook checks
shown separately.

相比 beta.6，已知 Codex 插件冲突现在可以在确认后迁移，仅停用列出的旧条目，保留源目录、
缓存和其他设置；配置变化或未知条目会阻止操作。Claude 仍需手动处理冲突。
安装结果改为紧凑摘要，集中显示路径和已核验状态，并单独列出会话与 Hook 的待检查项。

The Host loads the Plugin cache and starts MCP automatically in a new session.
No `~/.agents/skills` copy or separate MCP server install is needed. Check local
state with `qiongli doctor` and `qiongli install list`, then ask the new Host
session to list tools and call `qiongli_config_status`. Verify online providers
separately with `qiongli_literature_status`.

Host 在新会话中从插件缓存加载 Skills 并启动 MCP，无需复制到 `~/.agents/skills` 或另装服务。
先用 `qiongli doctor` 和 `qiongli install list` 检查本地状态，再在新会话中核对工具及
`qiongli_config_status`，在线服务另用 `qiongli_literature_status` 检查。

## Research, Graph and continuity / 研究、Graph 与连续性

Skills now leave more planning decisions to the model while retaining source
attribution, method limits and explicit write approvals. Journal workflows cover
both adapting to a selected venue and finding venues for an existing manuscript.
Humanizer guidance improves English and Chinese prose without altering evidence.

Skills 将更多规划判断留给模型，同时保留来源、方法限制和明确写入批准。期刊工作同时覆盖
“按选定期刊适配稿件”与“根据现有稿件寻找期刊”。Humanizer 改善中英文表达，不改动证据。

Use `$no-qiongli` in Codex, or “reply only” / “NoQ问理” / “仅回复”, for a
conversation-only answer. Optional context hooks are off on first local Plugin
installation and preserved on updates. They still need Host trust and a real
delivery check. Reply-only guidance is not a runtime permission lock.

可通过 `$no-qiongli` 或自然语言“仅回复”“NoQ问理”选择只在对话中回答。
可选上下文 Hook 首次默认关闭，更新时保留选择，仍需 Host 信任和实际触发核验。
仅回复是模型指导，不是运行时权限锁。

Research Graph connects canonical claims, evidence locations, citations,
decisions and gaps. `qiongli project graph view --project-id <prj_id> --open`
saves a private HTML snapshot and asks the OS to open it. Search and filter,
follow directed links and inspect source commands tied to that revision. Export
again after changes. The Host must first read authorized material and propose
records for approval; Graph does not automatically interpret arbitrary PDFs.

Research Graph 将规范记录中的论点、证据位置、引用、决定和缺口连接起来。上述命令保存
私有 HTML 快照并请求系统打开，支持搜索、筛选、有向关系和绑定版本的来源查询。
数据变化后需重新导出。Host 必须先读取授权材料并提出待批准记录，Graph 不会自动理解任意 PDF。

Try the [reproducible example](https://github.com/jxpeng98/qiongli/blob/v2.0.0/docs/examples/research-graph.md)
or its [中文页面](https://github.com/jxpeng98/qiongli/blob/v2.0.0/docs/zh/examples/research-graph.md).
Stage summaries retain findings, source links and changes; deletion is always
selected and performed by the user. Host subagents and cross-Host packets have
bounded task and source identities, with one coordinator checking results before
approved integration. Qiongli does not add a general agent scheduler.

阶段总结保留成果、来源和变化记录，删除内容始终由用户选择并亲自操作。子代理与跨 Host
交接明确任务和来源，由一个协调者检查返回结果，再按批准流程合入，不新增通用代理调度器。

## Migration, rollback and verification / 迁移、回退与验证

Back up research files and configuration before migration. Inspect duplicate CLI
installations with `qiongli setup`; different package managers do not overwrite
one another. Refresh the existing Plugin directory after changing the CLI. Old
shell commands are not universally compatible; follow the 2.0 guide and first try
a copied project. Keep the previous binary or exact package version for rollback.
Changing binaries does not undo data migrations; restore a data backup separately
when needed. No automatic cleanup of old installations or research files is added.

迁移前备份研究文件和配置，用 `qiongli setup` 检查多个 CLI 安装；不同包管理器不会互相
覆盖。更换 CLI 后刷新原 Plugin 目录。旧 shell 命令并非全部兼容，应按 2.0 指南先用项目
副本试运行。保留旧二进制或准确包版本用于回退；切换程序不会撤销数据迁移，必要时单独
恢复备份。本版不会自动清理旧安装或研究文件。

The publication workflow requires matching source/version, successful native
builds and installs on all three targets, empty-PATH CLI/MCP checks and verified
assets before creating the GitHub Release. It verifies public downloads before
dispatching npm, PyPI and Cargo publication; registries can therefore appear
later. This is the standalone CLI release, not completion of broader managed/App
or full 1.x replacement acceptance. Live Hook delivery, browser interactions and
cross-Host research journeys retain their own evidence requirements. Scientific
correctness, universal Host/model behavior and measured performance gains are not
established by passing packaging tests. No external Marketplace catalog change
or retirement of retained 1.x/Desktop source is part of this release.

发布工作流在创建 GitHub Release 前检查源码与版本、三平台构建安装、空 PATH 下的
CLI/MCP 和产物摘要；公开附件回读通过后才调度 npm、PyPI 和 Cargo，因此渠道包可能稍后出现。
本次是独立 CLI 正式发布，不表示整个托管产品、桌面替代或全量 1.x 迁移验收完成。
真实 Hook、浏览器交互和跨 Host 研究流程仍需各自的证据，打包测试不能证明科学结论、
所有 Host/模型行为或性能增益。本次不更改外部 Marketplace 目录，也不退役保留的 1.x/桌面源码。
