# Adapt external ideas

Borrow a method or review criterion when it solves a concrete gap. First check
whether an existing Skill, stage reference or template can express it. Credit the
source and preserve its licence requirements; popularity alone is not evidence
that the approach improves research quality.

| What you borrow | Where to adapt it |
|---|---|
| Research method or review criteria | Relevant guidance under `content/skills/` or `content/workflow/references/` |
| Output structure | `content/templates/` and the applicable research contract |
| Subject-specific knowledge | `content/subjects/` or a domain profile |
| Host interaction pattern | Shared workflow guidance, with narrow routing and reply-only behaviour preserved |
| Executable capability | The existing native service or Host integration, with a verified public tool contract |

Keep task IDs and source anchors stable. A broad external prompt can be separated
into existing tasks; it does not justify adding a second workflow framework.
Do not import arbitrary fixed role counts, mandatory discussion rounds or output
quotas. Retain evidence requirements, user permissions and method-specific limits.

Check the proposed change with relevant examples and affected tests. Report
self-review as self-review; an independent-agent claim requires a returned result
from an actual agent. See [extension guidance](../advanced/extend-qiongli.md) and
[editing conventions](../conventions.md).
