# research-skills `v0.7.0-beta.1` Release Notes

Date: 2026-05-06
Stage: Beta

## Highlights

- Introduced the plugin-first academic skills distribution, keeping one main `research-skills` plugin and one portable `research-paper-workflow` package for Codex, Claude Code, and Gemini.
- Replaced the plugin package symlink with a real bundled `research-paper-workflow` copy so new plugin sessions can load the full skill package without relying on repository-local symlink behavior.
- Added 16 thin plugin command wrappers under `plugins/research-skills/commands/`, mapping slash-style entrypoints such as `/paper`, `/lit-review`, `/study-design`, `/code-build`, `/submission-prep`, and `/rebuttal` to the same workflow package.
- Added plugin distribution contract tests covering Codex marketplace metadata, Claude plugin metadata, Gemini extension metadata, version alignment, command/workflow alignment, and marketplace artifact contents.
- Made the plugin distribution dry-run contract test tolerant of Windows runners where `bash` resolves to the WSL launcher without an installed distribution; the test now uses a usable Bash executable such as Git Bash when available and skips only when no Bash runtime exists.
- Added skill quality contract tooling and documentation:
  - `scripts/audit_skill_sections.py`
  - `scripts/upgrade_skill_contract_sections.py`
  - `docs/maintainer/skill-quality-contract.md`
  - `docs/maintainer/skill-quality-gap-report.md`
- Upgraded all 71 canonical academic skills to include the required quality sections and baseline anti-fabrication behavior:
  - `Purpose`
  - `Inputs`
  - `Process`
  - `Output Contract`
  - `Quality Bar`
  - `Common Pitfalls`
- Added `research-paper-workflow/references/academic-output-rubric.md` and wired the workflow skill to apply it when producing scholarly prose, synthesis, design, review, or submission artifacts.
- Updated install and architecture docs to explain the plugin / skill / CLI / orchestrator boundary:
  - native plugin or extension install is enough for client-side skills and workflow entrypoints
  - `full` runtime is still required for CLI commands, validators, `doctor`, release tooling, and `bridges.orchestrator`
- Clarified compatibility with older global `partial` / `full` installs:
  - official plugin installation does not automatically migrate or delete older global skill installs
  - users who keep CLI or orchestrator workflows should run `rsk upgrade --target all --doctor`
  - users moving fully to the plugin can preview old slash-command cleanup with `rsk clean --globals --dry-run`
