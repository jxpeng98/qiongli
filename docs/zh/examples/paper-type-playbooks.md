# 按论文类型选择路线

先说明论文的问题、材料和当前阶段。下面的示例展示共享 Skills 如何适用于不同研究，
具体必做步骤由已经约定的协议决定，不必因为选了某个论文类型就执行所有阶段。

## 系统综述（`systematic-review`）

可以这样请求：“请按我提供的协议协助完成这项综述，先检查检索策略和筛选标准。”

澄清问题后，设计检索、筛选并提取研究、评估质量，再综合证据，按综述类型选择报告检查。
保留检索和筛选日志、提取表、排除理由、质量评估，以及稿件与证据之间的关联。
已有文献集时，只有此前决定可查，才能从提取或综合阶段继续。
详见[严谨文献检索](../advanced/rigorous-literature-search.md)。

## 实证研究（`empirical`）

可以这样请求：“请根据可用数据和已约定的分析计划，审查这项政策效果研究的设计。”

Stage A/C 提供问题与设计指导，需要代码时使用 Stage I，再通过 Stage F 根据实际结果写作。
测量、识别和稳健性检查应与方法相符。研究已经完成时，可以从写作和报告检查开始，
但仍需保留设计与分析记录。

## 定性研究（`qualitative`）

可以这样请求：“请根据这些获准使用的访谈片段和分析备忘录起草发现部分，
保留来源位置、竞争解释与局限。”

由方法决定抽样、编码、比较和解释方式，按需使用设计、伦理、写作与报告指导。
不是所有定性研究都需要提出假设或进行统计稳健性检验。
保留抽样理由、协议、备忘录、证据记录，以及适用的报告检查表。

## 方法论文（`methods`）

可以这样请求：“请审查这个方法与评估设计，再整理代码规范和实现计划。”

Stage I 连接规范（I5）、计划（I6）、实现（I7）、审查（I8）和可复现性检查（I4）。
声称方法有所改进前，先明确比较方法、数据、指标与限制。
代码、评估输出和可复现性记录也是证据的一部分，写稿时应保留对应关系。

## 理论论文（`theory`）

可以这样请求：“请帮助澄清这个论证的机制，并根据提供的理论来源和竞争解释检查它。”

通过问题定位、理论梳理和综合形成论证，再写作并检查逻辑。
区分命题、假设条件、理论主张与实证证据。只有代码或模拟有助于回答研究问题时，才需要加入。

## 只推进一小步

明确要改哪个章节、决定或问题，以及应以哪些材料为依据。
模型可以选择较短的处理路径，同时保留必要证据和写入批准。
需要独立审查时，请求实际的[子代理或跨 Host 审查](../guide/multi-agent.md)。
