# Qiongli v2.0.0-beta.6

Beta.6 adds an offline Research Graph page, a reproducible example, lighter
research guidance and optional context hooks. It also adds a reply-only entry
and clearer records for delegated research work.

## Research Graph

Inspect claims, supporting evidence, citations, decisions and unresolved gaps in
one HTML file. Search and filter records, follow directed relations, return to a
previous selection, and copy a source command bound to the exported revision.
Proposed and rejected relations remain distinct from reviewed ones.

```sh
qiongli project graph view --project-id <prj_id> --save
qiongli project graph view --project-id <prj_id> --open
```

`--save` writes a new private snapshot; `--open` also asks the operating system to
open it. The page needs no server or extra runtime. It is a saved view, so export
again to see later changes. Existing snapshots and research files are preserved.

The bilingual Research Graph example includes synthetic reading notes, an
evidence ledger, decisions and a claim map. Its reproduction script uses the real
CLI and retains the HTML, snapshot and source-verification results. An unsupported
claim stays visible. See `docs/examples/research-graph.md` or
`docs/zh/examples/research-graph.md` in this tag.

Graph links come from normalized research records. The Host and model still need
to read authorized materials and prepare those records; the native CLI does not
automatically extract research meaning from arbitrary PDFs or folders.

## Skills, collaboration and hooks

Writing, study design, review and journal-fit guidance now emphasize the requested
outcome and applicable evidence. Both directions remain available: adapt a
manuscript to a selected journal, or find journals that fit the manuscript.
Canonical history, evidence limits and explicit write approvals remain in place.

Use `no-qiongli` (`$no-qiongli` in Codex), or say “reply only” / “NoQ问理” / “仅回复”,
to ask for an answer from the conversation without tool calls, agents or file
operations. This is model guidance, not a runtime permission switch.

Delegation guidance records task scope, source and candidate identity, observed
dispatches, partial results and stale or conflicting reviews. The Host supplies
agent execution and any cross-Host transport; Qiongli does not add a general
agent scheduler. One coordinator retains control of approved integration.

Plugin installation offers optional context hooks, off on first install and
preserved on updates. Use `qiongli install plugin --hooks context` to include them
or `--hooks off` to remove their configuration. Preview the commands before
confirming; Host trust and actual delivery are separate checks. Standalone Skills
exports do not install hooks.

## Install and update

Download the complete archive for macOS ARM64, Windows x64 or Linux x64 from
**Assets**, verify `SHA256SUMS`, extract, and run `./qiongli` (Windows:
`.\qiongli.exe`). No separate Python, Node.js, Rust or package manager is needed.
Linux requires glibc 2.35+. Host applications and online services are separate.

For package-manager installation, choose one channel:

```sh
npm install --global qiongli@next
python -m pip install --upgrade "qiongli==2.0.0b6"
cargo install qiongli --version 2.0.0-beta.6 --locked
```

npm requires Node.js 18+, PyPI Python 3.9+, and Cargo Rust 1.97+ plus a native
linker. Then run `qiongli install plugin` to refresh the registered Plugin source,
and open a new Host session. `qiongli doctor` and `qiongli install list` check local
registration; `qiongli mcp check` checks the current CLI's MCP protocol. Actual
Host tools still need session verification. Local Plugins include Skills and
Full MCP (32 tools); Marketplace platform archives use Lite MCP (14 tools).

Keep the previous archive or reinstall its exact package version for rollback.
Preserve research files and the Plugin source; switching binaries does not undo
data migrations. This Beta does not establish full 1.x migration acceptance,
measured performance gains, scientific correctness or universal Host/model
behavior. Local Graph DOM checks and synthetic examples do not establish real
browser rendering, clipboard permissions or live cross-Host collaboration.
