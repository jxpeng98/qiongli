# Qiongli v2.0.0-beta.4

Beta.4 connects installation, Plugin registration and the first MCP check. The
native CLI remains shared across GitHub downloads, npm, PyPI and Cargo.

## Install and start

Download the complete archive for macOS ARM64, Windows x64 or Linux x64 from
**Assets**, verify `SHA256SUMS`, extract, and run `./qiongli` (Windows:
`.\qiongli.exe`). No separate Python, Node.js, Rust or package manager is needed.
Linux requires glibc 2.35+. Host applications and online services are separate.

```sh
qiongli --version
qiongli install --interactive
qiongli mcp check
qiongli doctor
```

The installation guide recommends a Plugin containing Skills, the native program
and Full MCP. Choose Codex or Claude Code, review the export directory, then
confirm file changes and official Host registration separately. The default is
`qiongli-next` in your home directory; another Host needs a separate destination.
Standalone Skills and manual MCP configuration remain available choices. Bare
`qiongli install` still shows the read-only installation inventory.

MCP is compiled into the native program. The Host starts it from the Plugin
configuration; no separate MCP package or background terminal is needed. Local
CLI Plugins expose Full MCP with 32 tools. Native Marketplace platform archives
expose Lite MCP with 14 tools. Skills exports do not connect MCP automatically.

`mcp check` exercises initialization, tool discovery and one read-only call in
the current CLI process. It explicitly does not verify a Host session or online
provider access. Open a new Host session, list actual Qiongli tools and call
`qiongli_config_status`; inspect literature setup with `qiongli_literature_status`.

## Update and continue

Use the original channel to update the CLI:

```sh
npm install --global qiongli@2.0.0-beta.4
python -m pip install --upgrade "qiongli==2.0.0b4"
cargo install qiongli --version 2.0.0-beta.4 --locked
```

Choose one installer. npm requires Node.js 18+, PyPI Python 3.9+, and Cargo Rust
1.97+ plus a native linker. npm `qiongli@next` follows the prerelease channel;
`--ignore-scripts` is supported, followed by `qiongli setup` for version review.

Refresh existing Plugins with `qiongli upgrade plugin --target <codex|claude>
--destination <original-absolute-path/qiongli-next>`. Each Plugin has its own
executable. Previews show the previous export and current CLI versions; doctor
checks official registration and verified cache bytes. Changed files or conflicting
Plugins stop registration. Cancellation keeps exported files available for retry.
Version review leaves archive, uninstall and PATH changes to the user.

## Included since beta.3

- Codex Plugins expose the shared Qiongli Skill and 20 workflow shortcuts; the
  82 internal skill cards remain available on demand. Claude keeps one main Skill.
- Local Plugin diagnostics now distinguish registration, required refresh and
  unavailable observations, without claiming live-session readiness.
- Zotero Companion 0.3.1 declares support through Zotero 10.0.x, with isolated
  Zotero 10.0.2 checks covering notes, nested collections and approved writes.
- Package instructions are specific to their channel and use one CLI description.
  Build/staging checks reject mismatched CLI and embedded-content versions.
- English and Chinese Docs explain native installation, Graph evidence and stage
  continuity. A stage summary preserves originals; cleanup remains user-operated.

Graph remains a source-bound projection of reviewed research records. Structural
checks do not establish semantic extraction quality or a speedup over 1.x.
Project writes retain preview, explicit approval and revision checks. This release
does not change model settings or accept the full managed/Desktop migration program.
