# Qiongli v2.0.0-beta.5

Beta.5 makes Plugin installation and updates use the same guided flow. It also
clarifies command help and distinguishes CLI updates from bundled-content updates.

## Install and update

Download the complete archive for macOS ARM64, Windows x64 or Linux x64 from
**Assets**, verify `SHA256SUMS`, extract, and run `./qiongli` (Windows:
`.\qiongli.exe`). No separate Python, Node.js, Rust or package manager is needed.
Linux requires glibc 2.35+. Host applications and online services are separate.

```sh
qiongli --version
qiongli install
qiongli doctor
qiongli mcp check
```

In a terminal, `install` and `upgrade` open the guide. Choose Plugin to install
Skills, the native program and Full MCP together. `install plugin` also updates
existing verified content; `upgrade plugin` and `update plugin` remain aliases.
The guide discovers the chosen Host's registered source directory. You can use
`--target codex`, `--target claude` or `--target all`. Each Host has its own source
directory and separate file and registration confirmations. Cancellation or
failure stops subsequent Hosts. No package manager is run by these commands.

If another Qiongli Plugin is enabled, the guide names it before exporting files.
Disable that Plugin in the Host and retry. Qiongli does not remove unrelated
Plugins, archive old installations, change PATH or change model settings.

The Host loads Skills and MCP from its registered Plugin cache; no copy into
`~/.agents/skills` is needed. Successful registration reports the source and cache
locations. An export alone is not a completed installation. Use `doctor` and
`install list` to check registration, then open a new Host session and verify
actual tools. `mcp check` only exercises the protocol in the current CLI process;
it does not verify the Host session or online providers.

Standalone `install skills` exports guidance to `.qiongli-skills` and does not
register a Host or start MCP. Local CLI Plugins provide Full MCP with 32 tools;
native Marketplace platform archives provide Lite MCP with 14 tools.

## Other command improvements

In a terminal, bare `config backend`, `project graph`, `project capture`,
`project portfolio` and `app plan` show their available operations. Scripts retain
their existing output and exit codes. `install --help`, `content`, `doctor` and
the readable `update` status now point to the relevant installation or update
command. Project writes still require their explicit preview and approval inputs.

Update the CLI through its original channel before refreshing Plugin/Skills:

```sh
npm install --global qiongli@next
python -m pip install --upgrade "qiongli==2.0.0b5"
cargo install qiongli --version 2.0.0-beta.5 --locked
qiongli install plugin
```

Choose one installer. npm requires Node.js 18+, PyPI Python 3.9+, and Cargo Rust
1.97+ plus a native linker. Direct archives avoid these installation dependencies.
`qiongli upgrade cli` lists channel-specific upgrade steps. Bare `update` keeps
its managed native updater meaning; it does not upgrade npm, PyPI or Cargo.

For rollback, retain the previous archive or reinstall its exact package version.
Preserve project files and the existing Plugin source; source/cache verification
and confirmations still apply when refreshing content. Unknown or modified files
are not overwritten. Graph semantics, live-session readiness, performance gains
over 1.x and the full managed/Desktop migration program are not new claims of this
release.
