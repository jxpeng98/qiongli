# Qualify Codex and Claude Code first-usable v1

## Goal

Prove that the frozen Qiongli `v2.0.0-alpha.3` candidate is a usable local
research product inside authenticated Codex and Claude Code Hosts: Plugin and
Skills are discoverable, Full MCP is attached, a bounded research transaction
works, and Zotero truthfully provides both its direct Companion path and
file-import fallback.

This task qualifies the existing product. It does not resume App polish or
authorize a Community Alpha release.

## August 12 execution decision

The user directed permission-heavy work to remain open while code work moves
forward. This task therefore closes with an honest `partial` disposition after
recording exact-package Zotero evidence, exact system integration, one
authenticated Codex receipt, the reproduced Full/Lite route P0 and its focused
fix. Claude live model execution, new exact-head packaging and all publication
actions remain outside the authorized boundary; they do not block the next M1
code task.

## Requirements

### R1 — One exact candidate identity

- Download the existing aggregate artifact from promotion run `31439930097`;
  do not rebuild or silently substitute current `2.x` bytes.
- Verify source commit, candidate-set digest, target receipt, executable digest,
  embedded content digest, Plugin digest, and reported version before mutation.
- All Codex, Claude Code, MCP, Skill, and Zotero observations must name or be
  receipt-bound to that same candidate.

### R2 — Real-client isolation gate

- Run the repository's existing ignored real-Codex and real-Claude tests, or
  the existing candidate acceptance path that contains them, with absolute
  client executable paths and fresh isolated homes.
- Verify install, enablement/discovery, cache, bundled Lite MCP launch with an
  empty runtime `PATH`, removal, and preservation of unrelated canaries.
- Do not copy Host authentication or normal user configuration into isolation.

### R3 — Existing system Host activation

- Snapshot the Qiongli-owned registration/source state needed for exact
  rollback, then preview and apply the candidate through existing install
  authority. Preserve unrelated Codex and Claude configuration and plugins.
- Start fresh Host processes and directly observe Plugin enabled state, bundled
  Skill discovery, Full MCP connection, and the exact candidate digest in both
  Codex and Claude Code.
- Use each Host's existing authentication. Qiongli must not read, copy, log, or
  manage Host credentials.

### R4 — Bounded Host research journey

- In each Host, use the Qiongli Skill and Full MCP rather than a second child
  model process to perform one bounded journey: inspect readiness, run one safe
  literature query, inspect an existing project, and return a source-grounded
  result.
- Run non-interactively or in a fresh disposable conversation where supported,
  cap model spend, persist no conversation, and allow no unrelated writes.
- Reuse the existing R5C C5 contract for revision-bound handoff evidence when
  the prepared fixture is available. Do not create a parallel Host adapter or
  umbrella acceptance framework.

### R5 — Truthful Zotero qualification

- Both Hosts must observe the same Zotero Full MCP tools and truthful status.
- Verify file-import fallback without writing to the user's Zotero library.
- For direct integration, launch the real Zotero application with the bundled
  Companion in an isolated profile and disposable collection. Exercise bounded
  search, dry-run upsert, one explicitly approved apply, receipt replay
  rejection, and cleanup/removal.
- Direct Zotero readiness may be claimed only if the real Companion path passes;
  otherwise report the first version as partial rather than converting fallback
  success into a direct-integration claim.

### R6 — Evidence, rollback, and fix policy

- Retain only path-redacted, digest-bound receipts and bounded observations.
  Never commit credentials, Host conversations, system registrations, user
  paths, Zotero library data, or private acceptance roots.
- Restore the previous Qiongli-owned system integration if qualification fails;
  never replace unrelated Host state.
- Change product code only for a reproducible essential-path P0. Fix the shared
  owner once, add one focused regression, freeze a new exact source, and rerun
  only invalidated evidence. Evidence or documentation defects do not reopen
  the product candidate.
