# Qiongli v2.3.0

Qiongli 2.3.0 extends the 2.2.1 CLI-first research workflow with reviewed
retrieval-history persistence and recovery of saved research documents across
sessions. It preserves the existing project approval and revision checks.

穷理 2.3.0 在 2.2.1 基础上补齐检索记录的审阅保存，以及新会话对已保存研究文档的发现
和读取，继续使用现有项目审批与修订校验。

## Changes / 变更

- Append reviewed `retrieval_manifest.csv` attempts through the existing capture,
  exact preview, academic approval, filesystem approval and revision/CAS owner.
  Preserve earlier rows, failed attempts, source-packet hashes and unknown metadata.
- Read saved notes, source packets and retrieval history with `project document
  read` and Full MCP `qiongli_project_document_read`. Requests bind the registered
  project, revision, relative path and whole-file digest; bounded UTF-8 windows
  expose continuation offsets and refuse stale or unsafe sources.
- Discover latest saved bindings through existing receipts and captures with
  `project document list` and Full MCP `qiongli_project_document_list`. Only
  current documents provide read arguments; changed, missing and unavailable
  files retain their saved identity without adopting replacement hashes.
- Declare read-only, non-destructive and idempotent MCP hints for literature
  status, search planning and public fulltext reading. Only the fulltext reader
  declares external interaction. These hints do not grant Host approval or
  permission to write research data.
- Clarify secure ancestor requirements for local Plugin exports and keep
  paper-reading guidance capability-aware for older installed versions.

新增能力包括检索尝试的追加保存、已保存文档的有界读取，以及根据收据发现当前文档。
旧记录、失败尝试和来源哈希保留；文件发生变化时拒绝使用旧绑定。文献工具补充了 MCP
行为注解，现有审批、网络限制和研究数据写入边界继续生效。

## Packages / 软件包

The stable tag is `v2.3.0`. Matching npm, PyPI and Cargo packages are
`qiongli@2.3.0`, `qiongli==2.3.0` and `qiongli 2.3.0`. Standalone CLI archives
need no separate language runtime. Package-manager prerequisites remain Node
18+, Python 3.9+ and Rust 1.97+ respectively.

Use one installation channel once its package is available:

```sh
npm install --global qiongli@2.3.0
python -m pip install --upgrade "qiongli==2.3.0"
cargo install qiongli --version 2.3.0 --locked
```

## Compatibility and rollback / 兼容与回退

The CLI, Plugin/Skills and MCP remain the delivery surfaces. Full exposes 35 tools
and Lite 15; saved-project document discovery/reading belongs to Full. Users keep
their chosen Host and model configuration. Bibliography, Graph and complete B2
artifacts are not automatically produced by saving a note or retrieval row.

The new retrieval-manifest receipt artifact requires a supporting CLI. Older
binaries can reject receipts created by these extensions. Before upgrading,
retain project/configuration backups and the prior executable. Reverting a binary
or Plugin does not reverse project writes or downgrade receipt formats. No source
history is replaced merely to make an older version accept it.

旧版 CLI 可能无法读取新增类型的收据。升级前保留项目、配置和旧程序；切换回旧程序并不
撤销已经保存的研究记录，也不完成数据格式降级。

## Qualification boundary / 验证边界

The native targets remain macOS ARM64, Windows x64, Linux x64 and Linux
ARM64. The existing release owner qualifies each target's standalone CLI, npm and
wheel installations, and Codex/Claude Plugin archives against exact source bytes.
Linux distribution retains the glibc 2.35+ baseline; target-native qualification,
combined-package checks and Cargo source installation have their own evidence.

An isolated public-paper journey has exercised approved persistence and fresh
Codex recovery on development candidates, with explicit stale-source refusals and
preserved history. Its source-visible paper review retains unresolved numerical
conflicts and does not establish general academic accuracy, full B2 acceptance,
other Host/platform acceptance or experimental replication. Local qualification
and its exact-source limits are recorded in the
[execution plan](../../docs/superpowers/plans/2026-09-15-v2-0-1-transition-release-execution.md).

Stable publication uses the existing `main`/immutable-tag workflow. It requires
successful four-target distribution and combined-install checks at the exact tag,
verifies release assets before upload and checks public downloads before starting
npm, PyPI and Cargo publication. Each registry retains its own publication gates;
workflow dispatch alone does not establish package availability. External
Marketplace catalog changes, Desktop installers and announcement remain separate.
