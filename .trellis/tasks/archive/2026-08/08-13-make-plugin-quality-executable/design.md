# Technical Design

## Boundary

Use the existing two quality owners:

```text
academic case YAML + captured artifact fixture
  -> Evaluation Truth V1 typed assertions
  -> existing fail-closed case result
  -> thin 12-case batch status

canonical content/skills
  -> existing Skill audit
  -> staged distribution materializer/audit
  -> Codex/Claude Plugin bundle checks
```

No scorer, LLM judge, plugin-eval wrapper, assertion registry, or generated
content source tree is added.

## Academic Case Contract

Each file under `evals/academic_quality/cases/` adopts the existing V1 fields:

- `schema_version: "1.0"`;
- stable `case_id` and `pipeline`;
- `input.topic` containing the bounded scenario/prompt;
- non-empty `expected_outputs` whose artifacts are required and whose
  assertions use existing typed validators.

The batch wrapper maps each case ID to a contained fixture directory under
`evals/academic_quality/fixtures/` and calls the existing `run_case` API with
that output root. Captured fixture artifacts are small, redacted golden outputs:

- failure scenarios contain stable gate, severity, and finding evidence that
  typed assertions must observe;
- positive scenarios contain specific required methodological/evidence/reporting
  elements that typed assertions must observe.

The fixtures are not generated by a model during CI. They make the evaluator's
expected findings executable and mutation-sensitive while keeping model
performance claims out of scope.

## Batch Result

Replace dimension averages with the minimum aggregate:

- total cases;
- passed cases;
- failed/blocked cases;
- overall boolean/CLI exit code.

Truth remains inside `evals/runner/run_eval.py`; the batch wrapper iterates and
aggregates booleans only. An empty case directory is failure. Existing callers
that expected `dimension_scores` are migrated in the same atomic change rather
than kept behind a misleading compatibility shim.

## Canonical Skill Repair

Edit only the eight named Markdown sources. Put behavior in the semantic owner:

- Inputs/Process: missing prerequisite -> ask for it or record a gap/blocker;
- Quality Bar: finding -> interpretation -> implication must remain distinct and
  evidence-calibrated;
- Common Pitfalls/constraints: never invent task-specific evidence, rules,
  citations, data, feedback, statistics, or results.

The exact language may satisfy the structural audit, but review must also check
that it changes the Skill's usable instructions rather than merely matching a
keyword heuristic.

## Distribution And Compatibility

`content/workflow/SKILL.md` and `content/skills/` remain canonical. Existing
materializers produce staged Codex/Claude payloads in a fresh temporary root.
Existing capability and Plugin bundle tests verify identity and inclusion; no
generated mirror is committed.

The academic-quality command is internal, so removing its fake score return
shape is an intentional atomic test migration, not a public compatibility
promise. Evaluation Truth V1 receipt semantics stay unchanged.

## Observed Model Lane

Claude Code's native `plugin eval` can later run plugin/no-plugin ablation with
cost and threshold bounds. It needs model credentials, spend authorization, and
non-deterministic interpretation, so this design records it only as a deferred
manual evidence lane.

## Rollback

Revert the content/eval commit to restore the prior fixtures and Skill text. No
project data, Host state, App state, or schema migration is involved. The old
dimension averages must not be retained as fallback evidence after rollback;
they were never observations.
