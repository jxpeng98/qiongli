# All Chat App contract v1

## 1. Scope / Trigger

Use this contract when exposing committed `AllChatStateV1` data to the App.
It is a separate App boundary; it does not extend or renumber the frozen
schema 19 snapshot/intent/event protocol.

## 2. Signatures

The Rust owner is `apps/qiongli/src/all_chat_api.rs`:

```rust
pub const ALL_CHAT_APP_CONTRACT_SCHEMA_VERSION: u32 = 1;

pub fn project_all_chat_app_snapshot(
    state: &AllChatStateV1,
) -> Result<AllChatAppSnapshotV1, &'static str>;

pub fn all_chat_app_contract_schema_json() -> Result<String, &'static str>;
pub fn all_chat_app_contract_completed_fixture_json() -> Result<String, &'static str>;
pub fn all_chat_app_contract_cancelled_fixture_json() -> Result<String, &'static str>;
```

The serialized snapshot has `schemaVersion`, `runId`, `projectId`,
`expectedProjectRevision`, `generation`, `status`, `participants`, and ordered
`events`. Each participant exposes only `role`, `backendId`, and opaque
`sessionId`. Each event exposes `sequence`, `generation`, and a tagged `kind`.

## 3. Contracts

- The schema ID is
  `https://qiongli.dev/schemas/app/all-chat-app-v1.json`; version `1` is owned by
  Rust and generated as Draft 2020-12 with serialization semantics.
- The schema, completed fixture, and cancelled fixture are checked-in outputs of
  the Rust functions above. Do not hand-edit them independently.
- The boundary projects existing committed All Chat events. It does not expose
  streamed fragments, hidden reasoning, credentials, approval tokens, absolute
  paths, or ACP SDK types.
- `agent_turn_completed` and `agent_turn_cancelled` leave the run `running`;
  only a separate run terminal event changes run status. A cancelled fixture
  contains no partial coordinator message.
- Unknown object and event-union fields are closed. Revisions, generations, and
  event sequences stay within JavaScript's safe-integer range. Text, IDs,
  participants, and events retain the native All Chat bounds.
- `app-ipc/all-chat` starts at `absent -> 1` as an additive compatibility record
  inside the existing `app-ipc` family. `APP_API_SCHEMA_VERSION` remains `19`.

## 4. Validation & Error Matrix

| Condition | Result |
| --- | --- |
| Domain event cannot be represented by v1 | `all-chat-app-event-unsupported` |
| Schema serialization fails | `all-chat-app-schema-serialization-failed` |
| Fixture construction is invalid | `all-chat-app-fixture-invalid` |
| Fixture serialization fails | `all-chat-app-fixture-serialization-failed` |
| Checked-in schema or fixture differs from Rust output | Focused contract test fails |
| Unknown field, event tag, or out-of-range value | App decoder fails closed |
| Existing schema 19 source changes in this slice | Compatibility check fails |

## 5. Good / Base / Bad Cases

- Good: project a valid completed coordinator turn into one ordered v1 snapshot;
  the run remains active for later delegation or synthesis.
- Base: project a newly planned state with participants and no committed events.
- Bad: copy partial ACP updates into the snapshot, treat turn completion as run
  completion, expose provider secrets, or add All Chat fields to schema 19.

## 6. Tests Required

Run the focused Rust golden test, then the public-schema checks:

```bash
cargo test --manifest-path packages/qiongli-native/Cargo.toml \
  -p qiongli --lib all_chat_api::tests::generated_schema_and_representative_fixtures_are_stable \
  --locked
python3 tooling/scripts/validate_public_schema_policy.py
python3 -m unittest tests.test_public_schema_policy -v
```

Assert exact generated bytes, Draft 2020-12 plus the fixed schema ID, closed
objects/unions, safe-integer bounds, completed-turn ordering, and cancellation
without a committed message. `allChatCommittedSnapshotSchema` in `packages/qiongli-app-api/src/all-chat.ts`
decodes both Rust fixtures without defaults or casts.

## 7. Wrong vs Correct

Wrong: modify `desktop_api.rs`, increment schema 19, or define a second
frontend-owned All Chat shape.

Correct: add fields through a new version of this Rust-owned contract, regenerate
its schema and fixtures, record compatibility, then update the strict consumer
in the same slice.

## Stage 3b controls and transient App session — September 5, 2026

`apps/qiongli/src/all_chat_control.rs` owns the additive
`app-ipc/all-chat-control` v1 contract and the `qiongli_all_chat` Tauri command.
The generated `schemas/all-chat-control-v1.schema.json` and actual IPC golden
`tests/fixtures/all-chat-control-v1.json` belong to this owner. The TypeScript
client strictly decodes the response; schema 19 and the committed snapshots
above retain their exact bytes and meanings.

- Request tags: `read`, `start`, `prompt`, `control`, `close`. Start binds an active,
  ready registered project and its current revision; every prompt rechecks that
  revision. Cancel/permission/close remain usable after project drift.
- Native state retains one desktop session, up to 64 submitted turns, 2,048
  stream events and 8 MiB serialized content. A new session becomes the displayed
  session only after the previous worker is terminal; earlier private logs are retained. Other active project reads are rejected;
  a terminal session from another project does not block a new session.
- `nextTurn` is prompt admission identity; the caller sends `expectedTurn` and
  the native owner commits the intent to the private log before sending it to the worker or returning. Duplicate/stale prompts
  fail without changing state. ACP controls additionally match connection nonce,
  run, participant, session, turn and permission request. No lock spans an await.
- `starting/idle/active/closing/closed/interrupted` describe the retained session,
  not an All Chat run's authoritative terminal status. ACP `completed` ends only
  one turn. Cancel or failure retires the session. History stays visible, but
  continuation uses an explicit new session; load/resume are unavailable.
- Snapshot `revision` orders transient polling responses independently of ACP
  `sequence` and committed generation. Native collector rejects sequence gaps,
  wrong connection/run/role and exhausted bounds. Zod additionally rejects unknown
  fields/tags, unsafe integers, mismatched bindings and updates after turn end.
  The UI ignores stale polling responses and stops polling when unmounted.
- Source references are user-selected labels, recorded only. Explicit text/context
  is submitted; source bytes are never silently loaded or transmitted. No tool
  write authority or accepted result is created by a permission button.
- Only the debug-build in-process ACP demonstration is enabled here. It uses the
  production SDK/retained session/control paths without a process, provider,
  project read or file write. Codex/Claude remain unavailable in the App until 3c's
  tools/permission boundary. Release builds return `all-chat-development-only`.
  A browser replay is development-only and excluded by the production bundle check.
- Stage 3a now persists these observations through `all_chat_history.rs` and
  the existing project private storage owner. `read` restores the newest session
  and marks unfinished work interrupted after obtaining the OS lease. No saved
  controls or writes are replayed. The view is rebuilt from one canonical log;
  there is no second projection commit. Export and diagnostics exclude content.
  No packaged/live acceptance is inferred from these source checks.

Focused checks: native `all_chat` tests include actual Tauri MockRuntime invocation
with local origin, two turns, allow/deny, stale/duplicate controls, cancel/close and
unchanged project revision; the TypeScript contract test decodes those responses
and both committed fixtures. UI tests cover messages, permissions, interruption,
new-session controls and malformed responses. Build checks preserve prototype
hardening, schema 19 and External Host functionality.

## Stage 3a private history — September 5, 2026

`all_chat_history.rs` owns `all-chat-history-v1.schema.json` and its canonical
Rust fixture. This additive persisted contract does not change the control v1
wire shape, committed reducer snapshots or schema 19. Prompt, public update and
state records carry local sequence, timestamp and causal turn; stream updates
retain run/role/session/connection/turn and advertised capability bindings.

`qiongli-project::runtime_state` reuses private directories, bounded reads,
OS locks, atomic replacement, readback and digest CAS for
`<project>/.qiongli/all-chat/run_*.json`. One process lease owns writes per project.
Limits are 32 retained runs, 64 turns, 2,048 updates, 2,304 records and 8 MiB per
log; no automatic eviction. Nonterminal data reserves 4 KiB and three records
for closing/interruption. Research revision drift blocks new prompts but does
not prevent storing terminal observations. Invalid/future/noncanonical content,
sequence/causality/binding errors and stale CAS preserve existing bytes. A failed
commit poisons its writer because rename may have succeeded before readback.

Recovery rebuilds only the App observation view; it never invokes ACP or a
research mutation. Identical provider updates deduplicate; conflicting replay
fails closed. Saved pending permissions remain inactive. The UI renders unfinished
restored turns as interrupted and disables send/permission controls. A new run
retains older files; only the newest run is currently exposed. Lifecycle policy
owns stopped-writer backup/deletion and privacy. Task, attempt, checkpoint and
evidence receipt projections wait for their actual owner binding in Stage 3c;
private chat observations never become accepted evidence.

## Selected research excerpts and Capture review — September 5, 2026

`all_chat_research.rs` owns `app-ipc/all-chat-research` and
`app-ipc/all-chat-research-control` v2. Rust generates their schemas and real
IPC fixtures; `research.ts` is the strict consumer. Existing control/history v1,
committed snapshots and schema 19 retain their fields and meanings.

- `qiongli_all_chat_research` starts a research session on the existing
  `DesktopChat`, reads its context/candidate, or dismisses its latest candidate.
  Selection requires exactly two explicit nonoverlapping line ranges from the
  registered artifact reader. They can be different excerpts in one artifact;
  this does not yet select arbitrary PDFs or prove that two whole papers were read.
  V2 start additionally requires `contextAccess: "selected_excerpts"`. The UI
  obtains explicit local consent bound to project/revision/exact selections;
  changed scope cannot use that consent. Missing/unknown access fails before
  starting a session. The consumer checks returned selections against the request.
- Native context contains actual excerpts (16 KiB each), whole-artifact digests,
  exact line ranges, omitted-content flags, project revision and the embedded
  `paper-extractor.md` path/digest. Manifest version 2 authorizes exactly
  `fs/read_text_file` and declares three `readPaths`: `/qiongli-context/<sourceId>.txt`
  for each selected excerpt, then `/qiongli-context/method-<methodDigest>.md`.
  Native code installs those exact immutable bytes in the existing ACP read view;
  the UI validates the mapping and displays its three-resource scope. The method
  bytes are revalidated against their manifest digest before each turn. Local
  Workflow variants and MCP/Skills Host loading are not claimed.
- Research prompts reuse the existing prompt command. Native admission rejects
  extra caller context/source labels, revalidates source bytes and records the
  actual manifest in private prompt context before sending. Text is untrusted;
  graph links do not confer fact or review authority. A trailing newline cannot
  manufacture a readable source line.
- The in-process ACP fixture reads all three resources over ACP and compares exact
  returned bytes before emitting explicitly scripted comparison JSON. Each read
  emits bounded activity with distinct per-turn IDs; a failed read prevents a
  successful fixture outcome. This is real protocol/content loading, not model
  reasoning or validation of provider-native tools. A candidate
  requires a successful Stop outcome, closed structure, native run/turn/manifest
  bindings, byte limits, matching source lines/quotes and citations to both sources.
  Stream completion alone, partial text, permissions and model approval claims do
  not create candidates. The fixture does not call a model, process or network.

The v1 schemas/goldens remain historical evidence, never upgraded into tool
consent. The v2 wire change is `unsupported-breaking`: no safe automatic consent
migration exists. Old start payloads and candidates from an old manifest fail
closed. Private chat history v1 still restores observations without candidate or
tool authority. The named **Q04 research v2 integration/old-consumer gate** in the
current plan remains open before accepted v1 support can be removed or v2
published. This development-only source increment is not that approval.
- Candidate text edits are local review drafts until resubmission. Native checks
  every edited candidate again. `qiongli_research_capture` consumes the same
  `ResearchCandidate` contract and returns the existing schema-19
  `CaptureIntakePreview` event. It populates the existing project pending operation;
  its confirmation still routes through `ProjectStateService::apply_capture`.
  No parallel approval or artifact writer is introduced.
- `preview_capture_from_current_sources` binds exact source artifact digests into
  the private verified intake plan and checks them again under the existing write
  lock. Old `preview_capture` callers omit this optional guard and retain their
  exact digest semantics. Closed path readers and manifest/root/library checks
  remain authoritative. Capture identity includes stable session time and turn;
  repeat confirmation cannot append another copy. Capture intake remains pending
  history; the existing academic consolidation review writes research state and
  refreshes graph projections. No direct graph-cache/Reviewed-edge mutation occurs.
- Page remount observes native context and the latest candidate. Restart recovers
  private chat observations only; source authorization, unsaved candidate authority,
  editing and approvals are not resurrected. Old candidate submission fails.
  Starting another comparison explicitly loads current sources. Saved Capture and
  consolidated research state remain owned by project services.

Focused checks: native `--lib all_chat`, project `capture`, API research/All Chat
consumer tests, desktop All Chat/research/AppState tests, and public-schema policy.
Real adapter tool isolation, runtime authentication/loading, exact backend resume,
