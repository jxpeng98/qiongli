# Evidence-led writing quality

October 23, 2026. This increment prioritizes substantive synthesis and readable
bilingual prose. It follows the [public delivery observations](../../../public-visual/delivery/README.md),
whose source-faithful drafts repeatedly concluded with broad future-method lists.
The [observation](observation.json) binds original outputs, frozen inputs and
reviews. It does not treat faster startup, shorter text or fewer qualifications
as a content-quality score.

## Change and evaluation

Stage F now asks what different studies jointly establish about the question even
where estimates cannot be pooled or ranked. A remaining uncertainty should name
the claim it affects and what resolving it would change. Scholarly voice keeps a
measured result distinct from unknown mechanisms or longer-term outcomes, and
checks substantive equivalence across Chinese and English. A bilingual synthetic
coating example illustrates excessive caution that erases an observed result;
repairing such an existing conclusion belongs to substantive G4 review, not an
unannounced expression-only J2 edit. Existing evidence and write owners remain.

Two fresh writer processes use identical task/source bytes and the user's
configured model. Each performs two tasks: a bilingual review of the saved public
Kestin/Bastani education papers, and a separate Chinese Discussion based on the
existing fictional cluster-randomized error-identification record. The second
task tests whether an explicit positive finding survives unresolved mechanism,
attrition and longer-term questions. It is not another public empirical study.

Baseline and candidate guidance, prompts, source/config maps, images and criteria
are frozen before either run. Only Stage F and scholarly voice differ in the
guidance trees. Each writer has a fresh profile with access to its selected tree,
the synthetic record, the public project/config and original page images; the
other guidance tree and review criteria are outside its read permissions.
Strict effective config readback verifies three approved read-only Qiongli tools.
No network retrieval or project write is enabled. The processes overlap in time;
latency is descriptive, not a controlled speed comparison.

A third fresh model process receives anonymous outputs P/Q, original page text,
actual image-delivery metadata and the same source/quality criteria. It has no
guidance identity, writer profile, raw writer trace or MCP server. The mapping
is stored outside its read scope. It assesses both complete tasks and tests three
short conclusions against the synthetic record: one supported, one overstated
and one excessively cautious. The review request does not identify which is
which. Ties and different defensible syntheses are allowed.

This is an identity-blinded review in a fresh context using the same configured
model, not a different model, human/author or subject-expert assessment. There is
one output per task per variant; no population-level quality claim follows.

## Measurement and replay

Request compliance, argument continuity, explanatory depth, readable language,
factual/citation fidelity and inference fidelity are assessed separately using
answer spans and source locations. Chinese body lengths count non-whitespace
code points including punctuation/digits, excluding only source-anchor citations;
English lengths count whitespace-separated words with the same citation exclusion.
Headings and the requested recovery note are outside body targets. Both language
versions must retain the same consequential conclusions without matching syntax.

An October 23 correction in the preceding delivery report acknowledges that this
Chinese counting rule was already present in its loaded Stage F contract. The
four earlier bodies fit their 400–600 range (506/502/507/531); raw answers and
original reviews remain unchanged. The correction concerns compliance reporting,
not substantive quality.

Replay uses the retained drivers and existing capture/parser helpers in a new
private root. Preserve original answers before anonymization and review; retain
failures and reviewer disagreements. Public source packets, page renders, model
rollouts and authentication stay outside Git. Hashes prove artifact identity,
not source truth, reviewer independence or full reading coverage.

This increment preserves the configured models, installed profiles, project
bindings, task states and accepted evidence. Local integration targets `2.x`;
no push or publication is authorized.
