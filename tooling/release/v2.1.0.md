# Qiongli v2.1.0

Qiongli 2.1.0 adds DeepSeek Harness Plugin installation through the existing
`qiongli` npm package, keeps all 22 workflow entries available across Codex and
DSH, and extends source-bound external proposals to Claude Code, DeepSeek and
Antigravity. It also consolidates research continuity, literature delivery and
installation fixes developed after 2.0.0. Your Host keeps its configured model;
research writes still require preview, approval and revision checks.

穷理 2.1.0 将 DeepSeek Harness 插件纳入现有 `qiongli` npm 包，提供与 Codex
一致的 22 个入口和 Full MCP，并加入 Claude Code、DeepSeek、Antigravity 的
外部提案准备与收集接口。本版同时汇总 2.0.0 之后的研究连续性、文献交付与
安装修复；保留 Host 的模型设置以及研究写入的预览、批准和版本核验。

## DeepSeek Harness installation / DeepSeek 安装

In the official Desktop **Add plugin** dialog, select **Official npm registry**
and enter **`qiongli@2.1.0`**. The official local CLI supports the same package:

```sh
dsh plugin --profile desktop add qiongli@2.1.0
```

Replace `desktop` with your intended profile. For a local installation, replace
the package specification with the absolute path to the release's
`qiongli-2.1.0.tgz`. No global Qiongli CLI installation or installation script is
needed for the Plugin. It loads the bundled native executable for your platform.

桌面版直接输入包名即可；本地 CLI 可使用同一包名或发布附件中 npm 压缩包的
绝对路径。插件包含平台对应的原生程序，不需要另行全局安装 Qiongli。

The bundle supplies `qiongli`, `no-qiongli` and 20 workflow entries, with both
user and model invocation, plus 32 Full MCP tools. DSH 0.2 upgrades require
removing the installed `qiongli` Plugin through DSH and installing the new version.
Keep your profile and model settings; use one Qiongli bundle per profile. Start a
fresh session and check the actual Skill catalog and `qiongli_config_status`.
`qiongli install plugin --target deepseek` displays the official commands; the
terminal installation guide offers DeepSeek as choice 4.

## Changes since 2.0.0 / 2.0.0 之后的变更

- **External proposals:** the coordinator can prepare configured Codex, Claude
  Code, DeepSeek Harness and Antigravity CLI requests, then collect successful
  machine-readable results bound to the original handoff, source and candidate.
  The Host launches and supervises the process. Interrupted, unsuccessful or
  stale-source results cannot become completed research evidence.
- **Research continuity:** captured answers and handoffs retain source-linked
  decisions across research stages; synthetic journey checks remain distinct
  from actual research acceptance.
- **Literature delivery:** literature discovery, bibliography export and Zotero
  linkage use the existing source and proposal owners. Public-query/BibTeX checks
  do not establish approval or acceptance for a private real library.
- **Stable identity migration:** stable Plugins use `qiongli`; Alpha/Beta use
  `qiongli-next`. Source-status output is v2 in 2.1. Consumers relying on v1 must
  migrate. Verified older installation receipts remain readable, and updates
  reuse the registered source directory. Codex separately previews disabling
  previous enabled Plugin IDs; Claude retains its manual conflict resolution.
- **Distribution:** canonical content, native executables and release packets
  are source-bound. Hosted checks qualify all three platforms and their combined
  npm package before publication. Historical packages and tags remain immutable.

## CLI packages / CLI 安装

```sh
npm install --global qiongli@2.1.0
python -m pip install --upgrade "qiongli==2.1.0"
cargo install qiongli --version 2.1.0 --locked
```

Choose one channel. GitHub **Assets** also supplies standalone archives for
macOS ARM64, Linux x64 (glibc 2.35+) and Windows x64. Check `SHA256SUMS` before
extracting. Source-code archives are not executable packages. npm requires Node
18+, PyPI requires Python 3.9+, and Cargo installation builds with Rust 1.97+.

## Scope and rollback / 验证范围与回退

Actual isolated DSH 0.2.0-rc.2 checks on macOS ARM64 cover Plugin activation,
all 22 entries in the registry and browser-facing catalog service, resource
loading and Full MCP config status. They do not establish model task execution,
user-profile installation or two-Host research acceptance. External transports
require an authenticated Host with the declared machine-readable protocol.
Installed-user, real-library and broader collaboration acceptance remain open.

To roll back, install your previous CLI package, export its Plugin and re-enable
it in the Host. DSH rollback uses its own remove/install manager with the prior
version. Keep existing research records, profiles and caches; package upgrades
do not authorize their deletion. For migration and protocol details, read the
[CLI guide](https://github.com/jxpeng98/qiongli/blob/v2.1.0/docs/guide/cli-2x.md) and
[external Host guide](https://github.com/jxpeng98/qiongli/blob/v2.1.0/docs/advanced/external-host-coordination.md).
