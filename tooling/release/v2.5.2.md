# Qiongli v2.5.2 — clearer installation progress

This patch makes installation easier to follow by grouping each client's output
and reducing repeated diagnostics. The official installation commands, complete
approval previews and batch recovery behavior retain the 2.5.1 contracts.

## Installation display / 安装显示

- Separate each client, approval preview, execution and final summary. Successful
  DeepSeek steps retain one numbered result and elapsed time; repeated START lines,
  successful launch contexts and completed export receipts are hidden by default.
- On supported Unix terminals, update the current step and elapsed/limit time in
  one short line. Previous output remains available; no download percentage is
  inferred and terminal input mode is unchanged.
- Add `--verbose` for full safe diagnostics and `--plain` for concise append-only
  output. Both work with the installation guide and Plugin/all install or upgrade
  commands. Unsupported or narrow terminals, `NO_COLOR` and `CI` use plain output.
- Automatically expand failure diagnostics, retaining the exact failed step,
  original reason and targeted retry command. Full change previews remain visible
  before approval. A failed or declined client still allows later clients to run;
  closed input or output failure stops the batch safely.
- Correct stale installation labels to the existing Full MCP count of 35 tools.

默认显示按客户端分段，等待时在同一行更新步骤和耗时，减少重复日志和滚屏。
失败时仍自动显示具体步骤与处理命令，批准前的完整变更预览保持可见。

```sh
qiongli install plugin --target deepseek
qiongli install plugin --target deepseek --verbose
qiongli install all --plain
```

## Compatibility and verification / 兼容与验证

Full MCP retains 35 tools and Lite retains 15. This release introduces no research
schema migration, model changes or new write authority. Antigravity and Pi remain
experimental; Codex remains the primary research Host. Windows uses plain output.
The target set remains macOS ARM64, Windows x64 and Linux x64/ARM64 (glibc 2.35+).

Existing behavior verification covers 43 distinct affected Rust tests and 21
isolated terminal/refusal scenarios on Linux. In one synthetic successful DSH
installation, persistent output falls from 93 to 54 lines. These observations do
not establish real macOS terminal behavior or live Host/session qualification.

The [execution plan](../../docs/superpowers/plans/2026-10-05-v2-4-plugin-quality-release-plan.md#october-8--252-display-release-handoff)
records fresh candidate package checks separately from reused behavior evidence.
The immutable-tag release task must qualify all four targets and packages before
publishing GitHub assets and dispatching npm, PyPI and Cargo. Dispatch acceptance
does not establish completed publication. No announcement or external Marketplace
promotion is included.

Keep the previous CLI, managed Plugin sources and project/settings backups for
rollback. Switching executables does not reverse research writes. Update the CLI
through its original installation channel, then rerun Plugin installation to
refresh registered content and start a new Host session.
