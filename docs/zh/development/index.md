# 开发与维护

日常开发按仓库的 [CONTRIBUTING](https://github.com/jxpeng98/qiongli/blob/2.x/CONTRIBUTING.md) 执行：本地分支、受影响的检查、审阅、提交，再合入本地 `2.x`。

| 需要 | 页面 |
|---|---|
| 找到源码负责人 | [仓库结构](repository-structure.md)、[编辑约定](../conventions.md) |
| 理解架构与职责 | [系统架构](../architecture.md) |
| 增加研究指导 | [扩展穷理](../advanced/extend-qiongli.md)、[学科内容](../advanced/subject-packaging-model.md) |
| 调整命名、借鉴方法或发布 | [维护指南](../maintainer/index.md) |
| 维护保留的桌面端 | [本地桌面开发](local-desktop-build.md) |
| 查看旧清单与实施记录 | [历史资料](../legacy/index.md) |

当前路线图、台账与计划见[项目记录](../legacy/index.md#project-records)。历史设计不代替当前执行计划。

维护 1.x 分发时，参照[暂存目录生成与 npm 包契约检查](../../development/distribution-materialization.md)，生成产物保留在源码工作区之外。
