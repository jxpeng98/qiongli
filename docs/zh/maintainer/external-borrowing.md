# 借鉴外部方法

外部方法或审查标准能解决具体缺口时，再考虑引入。先看现有 Skill、阶段参考或模板能否承载，
注明来源并遵守许可证要求。一个方法流行，并不能证明它会改善研究质量。

| 借鉴内容 | 合适的修改位置 |
|---|---|
| 研究方法或审查标准 | `content/skills/` 或 `content/workflow/references/` 下的相关指导 |
| 产物结构 | `content/templates/` 与适用的研究契约 |
| 学科知识 | `content/subjects/` 或学科档案 |
| Host 交互方式 | 共享工作流指导，同时保留按任务处理和仅回复行为 |
| 可执行能力 | 现有原生服务或 Host 接入，并核对公开工具契约 |

保留任务 ID 和来源位置。外部的大型提示词可以拆到已有任务中，不必因此另建一套工作流框架。
不要照搬固定角色数量、强制讨论轮次或产物配额；证据要求、用户权限和方法限制仍应保留。

用相关示例与受影响的测试检查修改。自查应如实标注，独立代理审查则需要真实代理返回结果。
详见[扩展指南](../advanced/extend-qiongli.md)与[编辑约定](../conventions.md)。
