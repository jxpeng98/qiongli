# 选择研究任务

在 Host 中直接说明需要什么结果即可。Codex 可以使用 `$qiongli` 或列表中可见的工作流快捷入口，
不必先记住任务 ID。下表的 ID 方便查找共享指导、保持跨阶段记录一致，
它们不是原生 CLI 子命令。

## 从手头材料出发

| 目标 | 可以这样提出请求 | 相关指导与产物 |
|---|---|---|
| 把宽泛主题变成研究问题 | “请根据我提供的来源收窄这个主题，并指出尚未解决的假设。” | A1/A4：研究问题、范围和空白说明；需要时补充理论或假设工作 |
| 开展文献综述 | “先规划这项综述的检索，再提取我提供的论文，保留来源位置和局限。” | B1/B1_5/B2/B3 及相关综合、报告任务：检索、筛选、提取和文献图谱 |
| 设计研究 | “请根据研究问题、可用数据和已约定的协议检查这个设计。” | Stage C：设计、变量与数据可行性、竞争解释及有依据的稳健性检查 |
| 根据结果写作 | “请根据已确认的分析起草结果部分，保留估计值、不确定性和来源。” | 按需使用 F1/F2/F3：大纲、段落或全稿；需要时补充图表与报告指导 |
| 构建研究代码 | “请按提供的规范实现这个方法，再检查统计有效性与可复现性。” | I5/I6/I7/I8/I4：规范、计划、实现、审查及可复现性记录 |
| 准备投稿或返修 | “请把这些审稿意见对应到稿件位置，为每条意见提出回应。” | 按请求使用 H1/H2/H3/H4：投稿材料、回复矩阵或有来源依据的审查 |
| 只修一个问题 | “请在这份候选稿中处理 I8:P1-01，并检查受影响的结果。” | 保留问题 ID、候选版本及相关检查，不必重启完整流程 |

代码计划应在实现前明确关键假设，但无需规定每个日常编码选择。
同样，只修改一个章节，也不需要为所有研究阶段另建文件。

## 选刊与按期刊调整稿件

已经选定期刊时，用 A5 核对具体文章类型和投稿阶段的要求。
希望根据现有稿件推荐期刊时，用 H5 从贡献、方法和证据出发比较。
两条路径中，影响决定的期刊规定都需要现行来源。详见
[选刊与审稿](using-agent-skills.md#journal-fit-and-pre-submission-review)。

## 保存并继续推进

正式项目按需保留 `RESEARCH/[topic]/` 下的产物，并使用原有预览和批准流程。
后续工作沿用论点 ID、citekey、来源位置和方法限制。阶段完成需要交接时，可以请求阶段总结；
总结保留原始材料的链接，不删除文件。删除哪些文件，始终由你自己选择并操作。

只想聊天、不调用工具或处理文件时，使用[仅回复入口](../advanced/agent-skill-collaboration.md#reply-only)。
完整能力见 [Skills 指南](../reference/skills.md)，研究路线见
[论文类型示例](../examples/paper-type-playbooks.md)，安装和项目命令见 [CLI 指南](cli-2x.md)。
