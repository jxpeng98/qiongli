Qiongli 统一安装后的目标结构

如果 CLI 安装路径升级为“生成并注册本地 plugin”，Qiongli 会从两套入口收敛为一个主入口： canonical source 生成本地 plugin，plugin 负责 skill/workflow 暴露，统一 full MCP 负责 literature、orchestrator、doctor 和 task run。

推荐目标形态

Full CLI 生成本地 Plugin

完整安装不再只写入全局 skills 目录，而是生成客户端可管理的 plugin bundle，并把 MCP 指向 Python-backed full MCP server。

qiongli install --profile full --target all --surface plugin

一条主链路

核心变化是把 marketplace plugin 的容器形态和 CLI full runtime 的能力合并：plugin 成为客户端入口，full MCP 成为本地能力总线。

Source of truth

仓库中的 canonical source

  • content/workflow/ 定义 portable skill、workflow、templates、references。
  • content/distribution/plugins.yaml 定义 plugin metadata。
  • packages/python-qiongli/ 提供 CLI、full MCP、orchestrator。
→
Install output

CLI 生成本地 plugin bundle

  • 包含平台 manifest：.codex-plugin、.claude-plugin 等。
  • 内置 skills/qiongli-workflow 和命令 wrappers。
  • 写入 MCP 配置，但不保存 provider secrets。
→
Runtime

统一 full MCP server

  • 启动 qiongli mcp serve --transport stdio。
  • 提供 literature provider、orchestrator route、task plan/run、doctor。
  • arXiv 默认可用；其他 provider 使用共享本地配置。

结构会变成什么样

源码结构继续保持单一事实源；安装结果变成客户端 plugin bundle，而不是散落的 skill 目录加独立 MCP 配置。

安装 surface 的新边界

这样设计后，marketplace、full CLI、legacy skills install 都还能存在，但职责更清楚。

Marketplace

轻量 plugin

  • 面向没有本地 CLI runtime 的用户。
  • 内置 skill workflow 和 lite literature MCP fallback。
  • 适合快速启用一个客户端。
Full CLI

完整本地 plugin

  • 由 qiongli install 生成本地 plugin。
  • skill workflow、commands、full MCP 一起注册。
  • 默认承载完整 Qiongli 能力。
Compatibility

legacy skills 直装

  • 继续支持 ~/.codex/skills/qiongli-workflow。
  • 作为迁移和旧客户端兼容路径。
  • 不再作为 full profile 的理想主路径。

Codex 中的调用链

用户在 Codex 中看到的是 plugin 和 MCP tools；背后由本地 CLI runtime 执行 full MCP。

1

用户请求

例如 literature review、paper plan、robustness check。

2

Codex Plugin

加载 qiongli skill 和 command wrapper。

3

Workflow Skill

决定任务阶段、输出契约、质量检查。

4

Full MCP

暴露 literature、doctor、route、task plan/run。

5

Providers

OpenAlex、Semantic Scholar、Crossref、PubMed、arXiv。

6

Research Output

生成可审计的计划、证据、稿件或代码工件。

统一 MCP 里包含什么

CLI-generated plugin 不再绑定 marketplace 的 lite Node provider；它应当把 MCP 指向 full Python-backed server。

Literature

文献检索与 provider 配置

  • qiongli_config_status
  • qiongli_configure_provider
  • qiongli_collect_evidence
  • qiongli_test_provider
Orchestrator

完整研究任务路由

  • qiongli_orchestrator_route
  • qiongli_orchestrator_doctor
  • qiongli_task_plan
  • qiongli_task_run
