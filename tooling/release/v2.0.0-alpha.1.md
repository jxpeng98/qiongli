# Qiongli 2.0.0-alpha.1 macOS Release Runbook

Status: pre-publication; repository preparation only

Target: macOS arm64

Publication is blocked until the final exact-head ledger is complete. Windows
and Linux publication remain deferred.

## Security Boundary

The repository and Qiongli product never receive production private keys.

- macOS code signing uses an existing Developer ID identity and an existing
  `notarytool` Keychain profile.
- Update signing uses a canonical public authority document plus detached
  Ed25519 signatures produced by an external signer.
- The metadata tool accepts only public evidence, public key identifiers, and
  signature files containing exactly 128 lowercase hexadecimal characters
  with an optional final line feed.
- The external signer must sign the bytes represented by each
  `signing_preimage_hex` field, not the ASCII hexadecimal text.
- Every repository-produced receipt keeps `publication_allowed: false`.

## Required Inputs

- one exact-head unsigned macOS package directory from Native CI;
- the package source commit and package SHA-256;
- a canonical Alpha release-authority JSON file with separate release and
  launch-grant public keys;
- the selected release generation and key identifiers;
- production Developer ID, Team ID, and notarization access already configured
  on the maintainer machine;
- an external signer capable of signing the two launch-grant preimages and the
  later update-manifest preimage.

All paths passed below must be absolute. Every output path must not exist.

## 1. Sign And Notarize The Exact Package

```bash
QIONGLI_MACOS_SIGNING_IDENTITY="Developer ID Application: ..." \
QIONGLI_MACOS_NOTARY_PROFILE="qiongli-alpha1" \
QIONGLI_MACOS_EXPECTED_TEAM_ID="ABCDEFGHIJ" \
tooling/scripts/macos_alpha1_sign_notarize.sh \
  --artifact-dir "/absolute/native-ci-package" \
  --expected-source-commit "$SOURCE_COMMIT" \
  --expected-package-sha256 "$PACKAGE_SHA256" \
  --output-dir "/absolute/qiongli-alpha1-signed" \
  --production
```

The result must contain:

- `qiongli-desktop-2.0.0-alpha.1-macos-aarch64.signed-notarized.app.zip`;
- `qiongli-desktop-2.0.0-alpha.1-macos-aarch64.signed-notarized.dmg`;
- `qiongli-desktop-package.manifest.json`;
- `qiongli-desktop-2.0.0-alpha.1-macos-aarch64.signing.receipt.json`;
- the broader non-publishing signing and unsigned-acceptance receipts.

The ZIP remains the only self-update payload. The DMG is the first-install
surface and contains exactly `Qiongli.app` plus an `/Applications` link. In
production, the entry point signs and notarizes the application first, then
signs, notarizes, staples, mounts, and verifies the DMG independently. The
signing-boundary receipt binds both artifact digests; the updater's strict
receipt remains ZIP-only.

## 2. Prepare Launch-Grant Signing Preimages

Choose a validity interval that has not expired and a generation authorized by
both public key roles.

```bash
cargo run \
  --manifest-path packages/qiongli-native/Cargo.toml \
  --package qiongli \
  --example native_alpha1_update_metadata \
  --locked -- \
  prepare-grants \
  --signed-artifact-dir "/absolute/qiongli-alpha1-signed" \
  --authority "/absolute/qiongli-native-release-authority.json" \
  --generation "$GENERATION" \
  --published-at-unix "$PUBLISHED_AT_UNIX" \
  --not-before-unix "$NOT_BEFORE_UNIX" \
  --expires-at-unix "$EXPIRES_AT_UNIX" \
  --release-key-id "$RELEASE_KEY_ID" \
  --launch-key-id "$LAUNCH_KEY_ID" \
  --output "/absolute/qiongli-alpha1-grant-request.json"
```

Send only the two decoded `signing_preimage_hex` byte sequences to the external
launch-grant signer. Return the detached signatures as:

- `/absolute/qiongli-alpha1-codex.sig`;
- `/absolute/qiongli-alpha1-claude.sig`.

## 3. Prepare The Update-Manifest Signing Preimage

```bash
cargo run \
  --manifest-path packages/qiongli-native/Cargo.toml \
  --package qiongli \
  --example native_alpha1_update_metadata \
  --locked -- \
  prepare-manifest \
  --signed-artifact-dir "/absolute/qiongli-alpha1-signed" \
  --authority "/absolute/qiongli-native-release-authority.json" \
  --grant-request "/absolute/qiongli-alpha1-grant-request.json" \
  --codex-signature-file "/absolute/qiongli-alpha1-codex.sig" \
  --claude-signature-file "/absolute/qiongli-alpha1-claude.sig" \
  --output "/absolute/qiongli-alpha1-manifest-request.json"
```

Send the decoded `signing_preimage_hex` byte sequence from the manifest request
to the external release signer. Return the detached signature as
`/absolute/qiongli-alpha1-release.sig`.

## 4. Verify And Finalize Non-Publishing Beta Metadata

```bash
cargo run \
  --manifest-path packages/qiongli-native/Cargo.toml \
  --package qiongli \
  --example native_alpha1_update_metadata \
  --locked -- \
  finalize \
  --signed-artifact-dir "/absolute/qiongli-alpha1-signed" \
  --authority "/absolute/qiongli-native-release-authority.json" \
  --manifest-request "/absolute/qiongli-alpha1-manifest-request.json" \
  --release-signature-file "/absolute/qiongli-alpha1-release.sig" \
  --output-dir "/absolute/qiongli-alpha1-update-metadata"
```

Finalization fails closed unless it can verify the Beta release signature,
strict production signing/notarization receipt, exact manifest and archive,
Codex and Claude Code launch grants, release-key generation window, and Stable
stream rejection.

The output contains:

- `macos-aarch64.json`, ready to become the Beta endpoint response only after
  final authorization;
- `qiongli-alpha1-update-metadata.receipt.json`, which remains explicitly
  non-publishing.

## 5. Generate Supply-Chain Evidence

The evidence tool parses the locked dependency graph directly from
`Cargo.lock`; it does not require `cargo metadata`, a network connection, or a
fully populated multi-platform Cargo cache.

An unsigned exact-head package can be used to exercise the evidence pipeline:

```bash
cargo run \
  --manifest-path packages/qiongli-native/Cargo.toml \
  --package qiongli \
  --example native_alpha1_release_evidence \
  --locked -- \
  prepare-preflight \
  --artifact-dir "/absolute/native-ci-package" \
  --source-commit "$SOURCE_COMMIT" \
  --cargo-lock "/absolute/repository/packages/qiongli-native/Cargo.lock" \
  --build-run-url "https://github.com/jxpeng98/qiongli/actions/runs/$RUN_ID" \
  --build-started-at "$BUILD_STARTED_AT_RFC3339" \
  --build-finished-at "$BUILD_FINISHED_AT_RFC3339" \
  --output-dir "/absolute/qiongli-alpha1-supply-chain-preflight"
```

This is useful only as a non-publishing rehearsal. Final evidence requires the
same production authority and exact source across the signed desktop set,
signed Beta metadata, and production-signed three-file native candidate:

```bash
cargo run \
  --manifest-path packages/qiongli-native/Cargo.toml \
  --package qiongli \
  --example native_alpha1_release_evidence \
  --locked -- \
  prepare-production \
  --signed-artifact-dir "/absolute/qiongli-alpha1-signed" \
  --update-metadata-dir "/absolute/qiongli-alpha1-update-metadata" \
  --candidate-dir "/absolute/qiongli-alpha1-production-candidate" \
  --authority "/absolute/qiongli-native-release-authority.json" \
  --source-commit "$SOURCE_COMMIT" \
  --cargo-lock "/absolute/repository/packages/qiongli-native/Cargo.lock" \
  --build-run-url "https://github.com/jxpeng98/qiongli/actions/runs/$RUN_ID" \
  --build-started-at "$BUILD_STARTED_AT_RFC3339" \
  --build-finished-at "$BUILD_FINISHED_AT_RFC3339" \
  --output-dir "/absolute/qiongli-alpha1-supply-chain-production"
```

Production preparation re-verifies the signed/notarized update ZIP, the
separately signed/notarized first-install DMG, the public authority, both update
launch grants, Beta signature, Stable rejection, the production candidate, its
portable archive, and its release notes. It
then emits:

- a sorted SHA-256 asset manifest;
- a canonical CycloneDX 1.6 SBOM derived from the exact lockfile;
- a canonical in-toto Statement carrying SLSA Provenance v1;
- a canonical supply-chain receipt binding every input and output digest.

Every output remains `publication_allowed: false`.

## 6. Record Final Acceptance Gates

Create exactly these seven receipt files in one flat evidence directory:

- `finder-clean-machine.receipt.json`;
- `packaged-ui.receipt.json`;
- `real-clients.receipt.json`;
- `production-update.receipt.json`;
- `rollback.receipt.json`;
- `accessibility.receipt.json`;
- `exact-head-ci.receipt.json`.

Each receipt uses this schema. `gate_id` must match its filename, every check
must be `true`, and every attachment must be a regular file in the same
directory with the exact recorded size and SHA-256:

```json
{
  "schema_version": 1,
  "record_type": "qiongli-alpha1-publication-gate",
  "gate_id": "finder-clean-machine",
  "status": "passed",
  "publication_allowed": false,
  "source_commit": "40-or-64-character-lowercase-object-id",
  "release_set_sha256": "supply-chain-receipt-release-set-sha256",
  "observed_at": "2026-07-16T12:00:00Z",
  "actor": "maintainer-or-ci-identity",
  "environment": "macos-clean-machine-description",
  "checks": {
    "finder_launch": true,
    "empty_path_startup": true
  },
  "attachments": [
    {
      "file": "finder-clean-machine.log",
      "size_bytes": 1234,
      "sha256": "64-lowercase-hex-characters"
    }
  ]
}
```

The gate receipt is an evidence assertion, not a substitute for running the
named journey. Screenshots, logs, CI exports, and other attachments must not
contain credentials or private signing material.

## 7. Finalize The Non-Publishing Ledger

```bash
cargo run \
  --manifest-path packages/qiongli-native/Cargo.toml \
  --package qiongli \
  --example native_alpha1_release_evidence \
  --locked -- \
  finalize \
  --source-commit "$SOURCE_COMMIT" \
  --supply-chain-dir "/absolute/qiongli-alpha1-supply-chain-production" \
  --gate-evidence-dir "/absolute/qiongli-alpha1-final-gates" \
  --output-dir "/absolute/qiongli-alpha1-publication-ledger"
```

Finalization fails closed for preflight evidence, a mismatched source or
release-set digest, a missing/false gate, unbound attachment, unexpected file,
or modified checksum/SBOM/provenance record. Success writes the canonical
ledger and its SHA-256 sidecar, but the ledger still says
`publication_allowed: false`. Explicit maintainer authorization remains
required before any release mutation.

  selected public authority embedded;
- regenerate checksums, SBOM, provenance, candidate, release notes, desktop
  descriptors, and all receipts from that one artifact set;

- assemble and review the final immutable publication ledger;
- explicitly authorize publication before changing PR #63 from Draft, creating
  the tag, uploading assets, or updating the public Beta endpoint.
