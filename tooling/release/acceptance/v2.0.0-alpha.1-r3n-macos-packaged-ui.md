## Isolation Boundary

The package ran with an isolated HOME, isolated Qiongli config root, isolated
Codex and Claude Code config directories, and an empty `PATH`. No Rust, Python,
Node.js, Cargo, npm, pip, or external MCP executable was visible to the product
process. The host machine is not a clean machine, so this proves runtime-path
independence for the exercised journey rather than clean-machine acceptance.

All selected materialization targets were dedicated temporary directories.
The UI rejected a world-writable temporary parent with
`insecure-materialization-parent` and refused an accidentally selected,
non-managed parent with `unmanaged-materialization-target`. No real user
configuration, Marketplace, plugin cache, or Skills directory was mutated.

## Observed Journeys

### Application and global settings

- The packaged no-argument launcher displayed the `Qiongli 2` window.
- Accessibility exposed labelled Overview, Skills, MCP, Providers,
  Integrations, and Diagnostics navigation controls.
- Overview opened the supported global-settings editor at revision `0`.
- Enabling Crossref produced a digest-bound preview requiring explicit client
  configuration approval.
- Confirmation wrote `v2/settings.json` with owner-only `0600` permissions and
  advanced the revision to `1`.
- The packaged CLI reread revision `1`, `marketplace-lite`, Crossref enabled,
  and its expected `needs-public-setting` readiness without exposing private
  values.
- A later, separately started single App instance reopened the editor at
  revision `1` with `Enable Crossref` checked.

### Skills lifecycle

- The macOS native folder picker selected one explicit private target.
- The UI displayed the exact selected target and enabled materialize, verify,
  and remove operations only after target validation.
- Materialization required a digest-bound filesystem-write preview and
  explicit confirmation.
- The `skill-only` operation wrote 343 managed entries plus one canonical
  receipt. The receipt recorded explicit approval and these identities:

### Lite MCP and integrations

- `Run Lite MCP self-test` completed with `mcp-self-test-passed` while the

- Isolated `.codex` and Claude config roots were both classified as
  `Discovered but unmanaged` in an ordinary packaged session.
