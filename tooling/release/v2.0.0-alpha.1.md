# Qiongli 2.0.0-alpha.1 macOS Release Runbook

Status: pre-publication; repository preparation only

Target: macOS arm64

Publication is blocked until the final exact-head ledger is complete. Windows
and Linux publication remain deferred.

## Security Boundary

The repository and Qiongli product never receive production private keys.

- macOS code signing uses an existing Developer ID identity and an existing
  `notarytool` Keychain profile.
- Update signing uses a canonical public authority document plus detached
  Ed25519 signatures produced by an external signer.
- The metadata tool accepts only public evidence, public key identifiers, and
  signature files containing exactly 128 lowercase hexadecimal characters
  with an optional final line feed.
- The external signer must sign the bytes represented by each
  `signing_preimage_hex` field, not the ASCII hexadecimal text.
- Every repository-produced receipt keeps `publication_allowed: false`.

## Required Inputs

- one exact-head unsigned macOS package directory from Native CI;
- the package source commit and package SHA-256;
- a canonical Alpha release-authority JSON file with separate release and
  launch-grant public keys;
- the selected release generation and key identifiers;
- production Developer ID, Team ID, and notarization access already configured
  on the maintainer machine;
- an external signer capable of signing the two launch-grant preimages and the
  later update-manifest preimage.

All paths passed below must be absolute. Every output path must not exist.

## 1. Sign And Notarize The Exact Package

```bash
QIONGLI_MACOS_SIGNING_IDENTITY="Developer ID Application: ..." \
QIONGLI_MACOS_NOTARY_PROFILE="qiongli-alpha1" \
QIONGLI_MACOS_EXPECTED_TEAM_ID="ABCDEFGHIJ" \
tooling/scripts/macos_alpha1_sign_notarize.sh \
  --artifact-dir "/absolute/native-ci-package" \
  --expected-source-commit "$SOURCE_COMMIT" \
  --expected-package-sha256 "$PACKAGE_SHA256" \
  --output-dir "/absolute/qiongli-alpha1-signed" \
  --production
```

The result must contain:

- `qiongli-desktop-2.0.0-alpha.1-macos-aarch64.signed-notarized.app.zip`;
- `qiongli-desktop-package.manifest.json`;
- `qiongli-desktop-2.0.0-alpha.1-macos-aarch64.signing.receipt.json`;
- the broader non-publishing signing and unsigned-acceptance receipts.

## 2. Prepare Launch-Grant Signing Preimages

Choose a validity interval that has not expired and a generation authorized by
both public key roles.

```bash
cargo run \
  --manifest-path packages/qiongli-native/Cargo.toml \
  --package qiongli \
  --example native_alpha1_update_metadata \
  --locked -- \
  prepare-grants \
  --signed-artifact-dir "/absolute/qiongli-alpha1-signed" \
  --authority "/absolute/qiongli-native-release-authority.json" \
  --generation "$GENERATION" \
  --published-at-unix "$PUBLISHED_AT_UNIX" \
  --not-before-unix "$NOT_BEFORE_UNIX" \
  --expires-at-unix "$EXPIRES_AT_UNIX" \
  --release-key-id "$RELEASE_KEY_ID" \
  --launch-key-id "$LAUNCH_KEY_ID" \
  --output "/absolute/qiongli-alpha1-grant-request.json"
```

Send only the two decoded `signing_preimage_hex` byte sequences to the external
launch-grant signer. Return the detached signatures as:

- `/absolute/qiongli-alpha1-codex.sig`;
- `/absolute/qiongli-alpha1-claude.sig`.

## 3. Prepare The Update-Manifest Signing Preimage

```bash
cargo run \
  --manifest-path packages/qiongli-native/Cargo.toml \
  --package qiongli \
  --example native_alpha1_update_metadata \
  --locked -- \
  prepare-manifest \
  --signed-artifact-dir "/absolute/qiongli-alpha1-signed" \
  --authority "/absolute/qiongli-native-release-authority.json" \
  --grant-request "/absolute/qiongli-alpha1-grant-request.json" \
  --codex-signature-file "/absolute/qiongli-alpha1-codex.sig" \
  --claude-signature-file "/absolute/qiongli-alpha1-claude.sig" \
  --output "/absolute/qiongli-alpha1-manifest-request.json"
```

Send the decoded `signing_preimage_hex` byte sequence from the manifest request
to the external release signer. Return the detached signature as
`/absolute/qiongli-alpha1-release.sig`.

## 4. Verify And Finalize Non-Publishing Beta Metadata

```bash
cargo run \
  --manifest-path packages/qiongli-native/Cargo.toml \
  --package qiongli \
  --example native_alpha1_update_metadata \
  --locked -- \
  finalize \
  --signed-artifact-dir "/absolute/qiongli-alpha1-signed" \
  --authority "/absolute/qiongli-native-release-authority.json" \
  --manifest-request "/absolute/qiongli-alpha1-manifest-request.json" \
  --release-signature-file "/absolute/qiongli-alpha1-release.sig" \
  --output-dir "/absolute/qiongli-alpha1-update-metadata"
```

Finalization fails closed unless it can verify the Beta release signature,
strict production signing/notarization receipt, exact manifest and archive,
Codex and Claude Code launch grants, release-key generation window, and Stable
stream rejection.

The output contains:

- `macos-aarch64.json`, ready to become the Beta endpoint response only after
  final authorization;
- `qiongli-alpha1-update-metadata.receipt.json`, which remains explicitly
  non-publishing.
