# REL-903 forward-version immutability design

## Boundary

REL-903 is an acceptance proof, not a new migration feature. The existing
`GlobalSettingsStore` owns global settings reads; `ProjectStateService` and its
existing library/manifest storage code own project reads. The test must call
those owners instead of decoding JSON directly as the assertion mechanism.

## Test flow

1. Create one isolated home and one current project through existing public
   native services; create current global settings through
   `GlobalSettingsStore::replace`.
2. Record the supported bytes for `settings.json`, `library.json`, and
   `project_manifest.json`.
3. For global settings, increment only `schema_version`, call `load`, assert
   `UnsupportedSchema`, and compare exact bytes.
4. For the research-library index, increment only `schema_version`, call
   `snapshot`, assert `InvalidLibraryDocument`, and compare exact bytes.
5. Restore the supported library bytes. For the portable manifest, increment
   only `schema_version`, call `snapshot` and `preview_refresh`, assert
   `InspectionBlocked` plus `InvalidProjectDocument`, and compare exact bytes.

## Contracts and compatibility

- The supported schema version remains `1`; REL-903 introduces no new public
  identity.
- “Fail closed” means no successful typed load or mutation plan is produced.
- “Unmodified” means exact byte equality of the rejected future document.
- The manifest inspection health is intentionally redacted/coarse; callers do
  not receive project contents or a guessed downgrade path.

## Trade-offs

One cross-owner app test is smaller and more release-relevant than duplicating
separate crate tests. Existing config unit/integration coverage remains in
place. No checked-in JSON fixture is needed because the current documents are
generated by their real owners and only the schema number is changed.

## Risk and rollback

Direct test writes replace bytes only inside a temporary, service-created test
home/project and preserve existing file permissions. If a platform exposes a
real owner defect, fix only that shared owner and keep the same regression
test. Otherwise production code stays untouched and rollback is a normal test
and evidence revert.

## Evidence boundary

Focused and Slice evidence qualify only REL-903. They do not qualify REL-904,
candidate packaging, promotion, publication, or release authorization.
